## 1. The portfolio regression — root cause

Not a missing asset. `portfolio.html` line 899 carried a truncated string:

```js
links:[['Platform','https://bird-app.bolt.host'],['App','https://bird-app.bolt.host },
```

The string never closes and neither does the array. It throws at parse time,
so the entire 19-entry `WORKS` array never evaluated and the portfolio grid
rendered empty — silently, no visible error. Introduced in one of the three
"Update portfolio.html" commits on 2026-08-07.

Fixed. All 46 inline `<script>` blocks across the repo now parse.

This is the second time a syntax error silently disabled a whole feature — the
README records the same failure mode taking down the chat widget and the career
tool. `.github/workflows/ci.yml` now runs `node --check` on every `.js` file
**and** every extracted inline `<script>` on push. It catches this class of bug
instantly.

## 3. Chat: AI generation removed

The Moonshot/Kimi integration is gone entirely — no API key, no outbound
request, no generated text.

**Removed:** `assets/asilva-widget.js` (posted to `api.moonshot.cn` with a
visitor-supplied key), and `chat.html`'s iframe to `kimi.com`.

**Replaced by** one engine with two mount modes (floating widget + full-page),
which also closes the README's "consolidate the two chat surfaces" item.

The replacement is classical information retrieval running in the browser:
tokenizer, light stemmer, BM25 index, fuzzy typo correction, all reading
`credentials.json`. A turn resolves through intent rules → entity match →
retrieval → honest fallback. Below a confidence floor it says it doesn't know
rather than improvising.

### Three real bugs found during testing

- **The confidence gate was inert.** BM25 normalizes the top hit to 1.00
  always, so `can he build me a mobile game` matched "Capacity Building" at
  *full* confidence on the single shared token "build". Score-gating replaced
  with IDF-weighted query coverage.
- **Synonym folding was destroying signal.** Collapsing "climate" /
  "adaptation" / "cca" into one token flattened their IDF, so distinctive
  domain terms stopped being distinctive. Synonyms now expand the *query*
  rather than flattening the corpus.
- **Two intent collisions.** `who are his clients` returned a bio;
  `capacity building` returned calendar availability.

### Final test state

- 14/14 in-scope queries answer correctly, including typos
  (`whats teh salcedo projct` → Risk-Informed CDP Salcedo).
- 8/8 out-of-scope queries refuse honestly
  (`write me a poem`, `does he do blockchain`, `airspeed of a swallow`).

### Consequences worth internalizing

- The bot **cannot** state a metric that isn't in `credentials.json`.
  That file is now published copy, not scratch notes.
- It works offline. Nothing a visitor types leaves their browser.
- Answers are reproducible — same question, same answer, every time.
- Tuning: `COVERAGE_FLOOR` in `chat/engine.js`, `SYNONYMS` in `core/nlp.js`.
  New answers go in `assets/data/kb.json` — no code change.

`boot.js` also purges `asilva-kimi-key` from returning visitors' localStorage,
so no leftover credential sits in a browser for a service that's gone.

## 4. Architecture for blog / AI-Chorus

One entry point on every page:

```html
<script src="assets/js/boot.js" defer></script>
```

```
assets/js/
  boot.js                 ordered loader; add new modules to MODULES here
  core/
    util.js               escaping, storage, DOM, pub/sub bus
    nlp.js                tokenizer, stemmer, BM25 index, fuzzy matching
    data.js               THE single source of truth
    registry.js           module registry: deps, mounting, failure isolation
    router.js             hash router for module-owned views
  chat/
    engine.js             retrieval engine
    widget.js             chat UI (floating or inline mount)
  modules/
    blog.js               writing module
    ai-chorus.js          AI-Chorus (draft — see spec note below)
assets/data/
  kb.json                 authored conversational knowledge
  blog/index.json         post manifest
  blog/<slug>.json        post bodies
```

**Adding a feature:** write `assets/js/modules/<name>.js` ending in
`ASilva.registry.define({...})`, add the path to `MODULES` in `boot.js`, drop
`<div data-asilva-<name>>` where it mounts. Nothing else changes. The registry
resolves dependencies, skips modules whose mount point is absent on the current
page, and isolates failures so one broken module can't take a page down.

`core/data.js` is now the only reader of `credentials.json`, closing the
README's "forked into three copies" issue.

**Blog** ships working: JSON manifest + three posts, list and detail views,
deep-linkable at `#/blog/:slug`.

**AI-Chorus** is the honest gap. There is no spec for it anywhere in the repo,
so rather than guess silently it ships as `0.1.0-draft` with its working
assumption stated in the file header and the two swap points marked
(`VOICES` and `ask()`). If it means something other than multi-persona
answering, replace those two and the registration contract still holds.

## 6. ⚠ Before you deploy

corrected to **15**, your verified figure, and the one discipline that also read
18 was normalized. **`households_reached: "50000+"` was left untouched — it is
unverified against any CV record.** Confirm it or remove it. The engine prints
these fields verbatim.

**Service worker.** `CACHE_NAME` is bumped to `asilva-v4` in this package. It is

`portfolio.html`, drop it from `sw.js` precache, and remove it from the sitemap.
